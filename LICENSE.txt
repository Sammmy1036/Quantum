-------------------------------------------------------------------------------
Community contributions

Prices, station positions, landing pad sizes, planet alignments, pictures and
trade routes that Quantum users share through the Quantum community server are
contributed by those users. By sending a picture, a user confirms they took it
or otherwise have the right to share it, and agrees that it may be shown to
other Quantum users. Pictures can be reviewed, rejected, replaced or removed by
the server owner and their moderators at any time. Shared data is provided as
is, like the rest of the Software, and may be inaccurate or out of date.

-------------------------------------------------------------------------------
Community server sign-in

To keep the community server's data trustworthy, so that nobody can send
pictures, station positions, planet alignments, shared routes or job claims
under someone else's name, Quantum signs in to the Quantum community server
with the user's UEX datarunner secret key. Using these community features
requires this sign-in; price reports and everything that works with UEX's data
alone do not.

When Quantum signs in, it sends the secret key to the community server once,
over HTTPS. The server reads it only to ask UEX which UEX account it belongs
to, then discards it. The key is never stored or logged in the server, and it
is not used for anything else. The server returns a session token, which
Quantum keeps in settings.json and sends with later requests. The server keeps
only a one-way hash of that token, with the UEX username it belongs to and
when and from where it was last used. Sign-ins not used for 180 days end on
their own. Removing or changing the secret key in Settings signs that computer
out, and the server owner can end a user's sign-ins at any time, for example
when banning an account. The UEX Bearer Token is never sent to the community
server.

Anyone running their own community server receives users' secret keys in the
same way and should handle them with the same care. Users who don't want their
secret key to reach the community server can set "community_url" to "off" in
settings.json; Quantum then uses UEX's data alone.

-------------------------------------------------------------------------------
Moderation

The community server is run by its owner, who may appoint moderators and
admins to help. To keep shared data accurate and fair, they can review and
reject contributions, and suspend (for a set time), ban, or end the sign-ins of
an account that misuses the service, with a reason the user can see in
Quantum. Every action taken on the server's admin page is recorded with who
took it. A user who is suspended or banned can still use everything that works
with UEX's data alone.

-------------------------------------------------------------------------------
What the community server keeps, and deleting it

For each datarunner, the community server keeps their UEX username and avatar
link, the UEX report IDs and values of the price reports they send through
Quantum and what UEX decided about them, the pictures, station positions, pad
sizes, planet alignments, job claims, shared routes and bug reports they send,
and their sign-ins as described above. To protect the service it also keeps,
for a short time, the IP address and time of requests: rate-limit counters for
an hour, and a list of recent requests in memory until the server restarts.

A user can ask the server owner to delete everything the server holds about
them. The owner can erase it all from the admin page in one step; prices served
from their reports stop being shown, and their pictures are removed. UEX keeps
its own copy of the reports it received, under UEX's own terms. Encrypted
backups are not tied to a username, so users delete theirs themselves from
Settings > Backup. The record that an erasure was carried out (who did it and
when) is kept in the admin activity log for up to a year.

On the user's own computer, Quantum keeps a copy of the screenshot each price
report was sent with for 14 days, then deletes it. It is never sent to the
community server.

-------------------------------------------------------------------------------
Admin page accounts

People who run or moderate a community server sign in to its admin page with
their own account: a password, kept on the server only as a salted scrypt
hash, and a code from an authenticator app, whose secret is kept on the server.
Sign-ins are kept as one-way hashes of their tokens. The admin activity log
records each sign-in and change with the account, time and IP address. Anyone
running their own community server holds this data and is responsible for it.

-------------------------------------------------------------------------------
Backups

Quantum can back up a user's fleet, component swaps, waypoints, planned trade
routes and mapped stations to the Quantum community server. Backups are
encrypted on the user's own computer with a key made from their UEX Bearer
Token; the server stores them without being able to read them, and the token is
never sent to it (signing in uses the separate secret key, as described above). 
Anyone who has the token can open the backup, so users should keep their token 
private.

Backups are a convenience, provided as is with no guarantee that they will be
available or complete. A backup cannot be opened with a different token, so it
is lost if the user replaces their UEX token. Backups not updated for a year
may be removed, and the server owner may remove backups or end the service at
any time. Users can delete their own backup from Settings > Backup. Keep your
own copy of anything you can't afford to lose.
